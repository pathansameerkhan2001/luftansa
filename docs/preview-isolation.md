# Vercel Preview isolation

**Status:** code guard implemented (`src/lib/runtime/preview-isolation.ts`). **No infrastructure has been created or changed.** Preview deployments of `feature/homepage-cms` stay disabled (`vercel.json`) until every manual step below is approved and done.

## What the code enforces

Vercel sets `VERCEL_ENV` on every deployment. The app now distinguishes:

| Deployment | Condition | Behaviour |
|---|---|---|
| Production | `VERCEL=1`, production build, `VERCEL_ENV=production` | **Unchanged.** Same table default, same S3 credentials, same CDN. |
| Preview | `VERCEL=1`, production build, any other `VERCEL_ENV` (including missing) | Fails closed (below) |
| Local | everything else | Unchanged: DynamoDB Local and the local media folder only |

On a Preview, the database and media storage are only used when **all** of these hold. Otherwise they are disabled: the storefront shows its built-in fallback content, and admin writes, uploads and deletions are refused.

- `DYNAMODB_TABLE` is set explicitly (no fallback to `luftansa-store`), is not a production table, and contains `preview`.
- `AWS_S3_BUCKET` is set explicitly, is not a production bucket, and contains `preview`.
- `AWS_ROLE_ARN` is set. DynamoDB and S3 then use **only** that OIDC role. `AWS_ACCESS_KEY_ID` / `AWS_SECRET_ACCESS_KEY` are ignored on Preview, even when present.
- `ASSET_CDN_URL` is ignored on Preview: media comes from the Preview bucket through `/media/...`.

Admin → Dashboard → System status shows the deployment environment and, on a Preview, which variables are missing or refused (names only, never values). Problems are also logged once as `[preview-isolation] … disabled: …`.

Production resource names that a Preview refuses: `luftansa-store` (table) and `luftansa-store-assets` (bucket). Update `PRODUCTION_DYNAMODB_TABLES` / `PRODUCTION_S3_BUCKETS` if production resources are ever renamed.

## Manual steps (each needs explicit approval; none has been done)

Order matters: steps 1–2 protect Production; nothing may be pushed with Preview deployments enabled until steps 1–7 are done.

1. **Production safety first.** Enable point-in-time recovery on `luftansa-store`.
2. **Vercel variable scoping (read, then change).** In Vercel → Settings → Environment Variables, set `AWS_ACCESS_KEY_ID`, `AWS_SECRET_ACCESS_KEY`, `DYNAMODB_TABLE`, `AWS_S3_BUCKET`, `ASSET_CDN_URL`, `AUTH_SECRET`, `COGNITO_CLIENT_ID`, `AUTH_REDIRECT_URI`, `AUTH_LOGOUT_REDIRECT_URI` and `ADMIN_EMAILS` to **Production only**. The code guard already ignores production keys on Preview; this is a second layer.
3. **Preview resources (AWS):**
   - DynamoDB table `luftansa-store-preview`: on-demand billing, keys `pk`/`sk` (String) and indexes `GSI1` (`GSI1PK`/`GSI1SK`) and `GSI2` (`GSI2PK`/`GSI2SK`), projection ALL (same as `scripts/local/setup.ts`). Point-in-time recovery on.
   - S3 bucket `luftansa-store-preview-assets`: private, Block Public Access on, CORS allowing only the stable Preview host (for presigned uploads).
4. **Vercel OIDC + Preview role.** Enable OIDC Federation (team issuer) if it is not already on. Create IAM role `luftansa-vercel-preview`:
   - Trust: `sts:AssumeRoleWithWebIdentity` for the Vercel provider, with conditions `aud = https://vercel.com/<TEAM_SLUG>` and `sub = owner:<TEAM_SLUG>:project:<PROJECT_NAME>:environment:preview`. Do **not** add the preview `sub` to the production role.
   - Permissions: the same actions as the production policy in `docs/aws-oidc-setup.md`, on `table/luftansa-store-preview` (+ `/index/*`) and the folders of `luftansa-store-preview-assets` only (no write to `logo/*`).
   - An explicit `Deny` of `dynamodb:*` and `s3:*` on `table/luftansa-store` (+ `/index/*`), `arn:aws:s3:::luftansa-store-assets` and `arn:aws:s3:::luftansa-store-assets/*`.
5. **Cognito.** Create a new public app client `luftansa-admin-preview` in the existing pool: Authorization code + PKCE, no client secret, same scopes. Callback `https://<stable-preview-host>/api/auth/callback`, sign-out `https://<stable-preview-host>/admin/login`. Use one stable host (the branch alias or a custom Preview domain); Cognito does not accept wildcards. Leave the production app client unchanged.
6. **Preview-scoped Vercel variables:**

   | Variable | Value (Preview only) |
   |---|---|
   | `DYNAMODB_TABLE` | `luftansa-store-preview` |
   | `DYNAMODB_REGION`, `AWS_REGION` | `ap-south-2` |
   | `AWS_S3_BUCKET` | `luftansa-store-preview-assets` |
   | `AWS_ROLE_ARN` | ARN of `luftansa-vercel-preview` |
   | `ASSET_CDN_URL` | not set |
   | `COGNITO_REGION`, `COGNITO_USER_POOL_ID`, `COGNITO_DOMAIN` | same as Production (not secret) |
   | `COGNITO_CLIENT_ID` | the Preview app client |
   | `AUTH_REDIRECT_URI`, `AUTH_LOGOUT_REDIRECT_URI` | the stable Preview host URLs |
   | `AUTH_SECRET` | **new** random value (≥ 32 characters), generated by you, never copied from Production |
   | `ADMIN_EMAILS` | testers only |
   | `AWS_ACCESS_KEY_ID`, `AWS_SECRET_ACCESS_KEY`, `DYNAMODB_ENDPOINT`, `LOCAL_MEDIA_DIR`, `COGNITO_ISSUER` | not set |

7. **Deployment Protection** on for Preview, plus one "Protection Bypass for Automation" token, kept only on the machine that runs the tests.
8. **Seed** the Preview table with sanitized fixtures only (product types and the approved announcement/hero test content). Never copy production data.
9. **Then** remove the `feature/homepage-cms` rule from `vercel.json` (or deploy the branch once by hand). Before any test that writes, open System status on the Preview and confirm: environment "Preview: isolated", table `luftansa-store-preview`, bucket `luftansa-store-preview-assets`, credentials via OIDC.

## After merging to `main`

Open System status on Production and confirm the "Deployment environment" row reads **Production**. Production depends on `VERCEL_ENV=production`, a Vercel system variable that is exposed together with `VERCEL=1`, which Production already relies on. If the row ever reads Preview, the database and media are disabled (fail closed), not pointed elsewhere.
